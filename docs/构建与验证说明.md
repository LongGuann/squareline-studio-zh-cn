# 构建与验证说明

## 渲染时翻译

`构建汉化.py` 在 `UnityEngine.UI.dll` 中加入独立翻译辅助类型，使用有序词典和二分比较查找显示文字，再将以下三个方法的文字读取接入翻译：

- `Text.OnPopulateMesh`
- `Text.get_preferredWidth`
- `Text.get_preferredHeight`

`Text.get_text` 和 `Text.set_text` 保持原始字节。可编辑输入框的实际文字直接返回原文，占位文字和只读标签可以翻译。

汉化词典匹配只影响界面显示，不写回工程属性、对象标识、代码模板或 LVGL 预览内容。

## 中文字体

构建器在 `sharedassets0.assets` 中新增中文后备字体、材质和纹理三个对象，并为原来的三个字体增加后备引用。原来的西文字体及其他原始资源对象保留。

默认使用本机的 `DroidSansFallbackFull.ttf`，可以指定：

```bash
export SQUARELINE_CJK_FONT="/path/to/DroidSansFallbackFull.ttf"
```

其他字体未单独验证。构建后的验证程序会检查词典所需字符是否有字形覆盖。

## 本地构建

所有命令从仓库根目录执行。`SQUARELINE_APP_DIR` 指定应用目录。

```bash
export SQUARELINE_APP_DIR="/path/to/SquareLine_Studio_Linux_v1_6_3"
python 汉化补丁/工具/生成词典.py
python 汉化补丁/工具/构建汉化.py
python 汉化补丁/工具/验证汉化.py --built-files
```

原版备份、生成产物和每次构建的校验清单位于 `.gitignore` 排除的本地目录中。安装补丁前，先退出应用并执行 `bash 启用中文.sh`。

若本机应用已经汉化，应将最初的原版备份按相同路径放到 `汉化补丁/备份/`。构建器会检查每个输入文件的 SHA-256，不会对未知文件继续构建。

## 验证程序

- `--built-files` 检查仓库中的生成文件，适合安装前运行。
- 不带参数时检查 `SQUARELINE_APP_DIR` 中已经安装的文件。
- 比较全部原方法，要求只有上述三个原有方法发生预期修改。
- 解释执行新增 IL，检查词典查找、跳转、输入框保护、空值、空格和动态前缀。
- 检查原非字体资源对象的字节，以及全部中文词条的字形覆盖。
- 检查构建时记录的 `Assembly-CSharp.dll` 指纹保持一致。
- 若本机还保留原始验证时的临时 POS 工程和导出目录，会追加保存与导出检查；未提供这些临时夹具时会明确记录为未执行。

原始集成验证使用官方随附 POS 示例的独立副本，成功导出 30 个文件。工程中的名称、文本和枚举值保持原样；应用按其正常行为升级了旧示例的样式定义。

## 维护词典

主要编辑入口是 `汉化补丁/工具/基础词条.tsv`，每行使用 Tab 分隔英文原文和中文译文。修改后重新生成词典、构建并验证。

界面新增拼写可以加入 `界面原文清单.json`。生成器保留实际使用的拼写和明确配置的词条，避免为大量无用变体生成额外 IL。

## X11 界面验证辅助工具

`界面验证.py` 只用于维护时操作本机 SquareLine 窗口，另外需要 `python-xlib`、Pillow；其剪贴板操作还使用系统 GTK 3 Python 绑定。它不是构建或日常使用的必需步骤。

自动验证的报告不替代实际界面检查。版本更新时还应人工检查启动页、菜单、设置、属性区和真实工程导出。
